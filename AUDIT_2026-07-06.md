## Bugs

### 1. Dodge i-frames (and GM godmode) are client-only — no protection in MP — **High**
`PlayerMovement.DodgeRoutine` sets `health.isInvulnerable = true/false` (`PlayerMovement.cs:256,277`)
on the local client's `Health`. Damage runs on the server (`EnemyController.cs:220`,
`AbilityCaster` dispatch, `EnemyProjectile.cs:43`) against the server's `Health`, where the flag is
read (`Health.cs:133`). `isInvulnerable` is a plain `[HideInInspector] public bool`
(`Health.cs:126`), not a SyncVar, so the server never sees the dodge. Player takes full damage
mid-roll. Identical defect: `GmConsole.cs:261` sets `_health.isInvulnerable` client-side.
**Minimal fix:** route the i-frame through the server — add a `[Command] CmdSetInvulnerable(bool)`
on the player (or fold i-frames into a server-side dodge state), and have the client call it at
roll start/end instead of writing the field directly. Keep the local write for editor-solo play.

### 2. `GmConsole.cs` has no `#if !UNITY_SERVER` guard — **Medium**
600-line client-only console (`GmConsole.cs:1-15`, uses `InputSystem`, `TMPro`, `UnityEngine.UI`)
with **zero** `UNITY_SERVER` guards (`grep` → none). It compiles into the dedicated server build
and instantiates input/UI paths on a headless process. This is the exact bug flagged in every
prior status doc and still unfixed despite Roadmap 1.5 being marked done.
**Minimal fix:** wrap the class body in `#if UNITY_EDITOR || !UNITY_SERVER … #endif`
(the mandated pattern), matching `PlayerIdentity`/`FloatingDamageText`.

### 3. Bare `#if !UNITY_SERVER` strips client code in editor play-mode — **Medium (High for velocity)**
31 files use `#if !UNITY_SERVER` without the `UNITY_EDITOR ||` prefix, e.g.
`CombatSessionTracker.cs:1`, `EnemyHealthBar.cs:1`, `ClericHealVFX.cs`, `CombatAudio.cs`,
`FloatingDamageText` call-sites, `IronWardenController.cs`. `CLAUDE.md` states the rule verbatim:
the editor build target is Dedicated Server, so `UNITY_SERVER` is defined in-editor and these
blocks vanish in play-mode. Net effect: when the owner playtests in-editor, health bars, damage
numbers, heal/combat VFX/audio, and combat-session tracking are all inert — features that are
actually fine in a shipped client build look broken. **Minimal fix:** mechanical
find-and-replace `#if !UNITY_SERVER` → `#if UNITY_EDITOR || !UNITY_SERVER` across those 31 files
(only where the intent is "client-only," which is all of them here).

### 4. `PlayerMovement` inconsistent `Keyboard.current` null handling — **Low**
`Keyboard.current.wKey.isPressed` is dereferenced unguarded (`PlayerMovement.cs:149-152`), but the
jump check 15 lines later guards it (`PlayerMovement.cs:167`). On a device with no keyboard this
NREs every frame. **Minimal fix:** early-return in `Update` if `Keyboard.current == null`.

### 5. Shield amount is server-only, never synced — **Low**
`_shieldRemaining` (`Health.cs:28`) is a plain field mutated server-side; it is not a SyncVar and
has no RPC. A client `ShieldValueHUD` cannot read it, so shield UI can't reflect true value in MP.
**Minimal fix:** make it a `[SyncVar]` (or push via the existing `onHealthChanged` event with a
shield param) — cheap, non-breaking.

## Fundamental Flaws

### A. Two competing combat/entity stacks — *fix soon, cheap now, expensive later*
`EnemyController.cs` (Mirror-native FSM, `[Server]`) and `EnemyAI.cs` (VPS-origin) both exist and
both call `TakeDamage` (`EnemyAI.cs:118`, `EnemyController.cs:220`). Every new combat feature has
to guess which is canonical, and prefabs can silently wire the wrong one. This is Roadmap 0.5,
still undecided. **Correction:** pick `EnemyController` as canonical (it matches the `[Server]`
discipline), archive `EnemyAI.cs`/`PlayerHealth.cs`/`EnemyTemplateRegistry.cs` outside `Assets/`,
and grep prefabs for stale references. Small diff, removes a whole class of ambiguity.

### B. Client-set combat flags on a server-authoritative Health — *fix now*
Bug #1 is a symptom of a pattern: `Health` correctly refuses client mutation via
`CanMutateCombatState()` (`Health.cs:284`), but `isInvulnerable` bypasses that gate as a public
field written from client scripts. Any future "block/parry/phase" mechanic will hit the same trap.
**Correction:** treat `isInvulnerable` (and any future defensive toggle) as server-owned — set only
inside `[Server]`/`[Command]` paths. One-time discipline fix, prevents recurring exploit surface.

### C. Guard-pattern drift is now systemic, not a one-off — *fix now, mechanical*
13 files use the correct `#if UNITY_EDITOR || !UNITY_SERVER`; 31 use the bare form; one file
(`AbilityCaster.cs`) mixes both. Without a lint/check this ratio will keep drifting and in-editor
testing becomes unreliable. **Correction:** the find-and-replace in Bug #3 plus a one-line grep in
the verification bar (`git grep -n '#if !UNITY_SERVER'` must return zero) to keep it fixed.

### D. Documentation can't be trusted as source of truth — *fix now, low cost*
SNAPSHOT/ROADMAP are dated 07-03 and already contradict the tree (scene renames, Roadmap 1.5
falsely ✅). Since `CLAUDE.md` designates these as the read-first context, stale docs mislead every
future session. **Correction:** a short "reconcile docs" pass after each batch (the verification
bar already asks for this — enforce it).

## Storage & Bloat Reduction  *(your follow-up ask)*

Current on-disk: `.git` **5.4 GB**, `Library/` **9.9 GB**. Findings and the payoff for each:

1. **Reclaim ~10 GB instantly, zero risk:** `Library/`, `Temp/`, `Logs/`, `Build/`, `obj/` are all
   correctly in `.gitignore` (Unity regenerates them). Deleting `Library/` locally frees ~9.9 GB
   now; Unity rebuilds it on next open. Nothing tracked lives there (`git ls-files Library/` → 0).
2. **The 5.4 GB `.git` is the real problem: `.glb`/`.gltf`/`.zip` never went to LFS.**
   `.gitattributes` LFS-tracks `.fbx/.obj/.png/.jpg/.blend/.3ds/.dae` but **not** `.glb`, `.gltf`,
   or `.zip`. The 50–76 MB Tripo rigs (`Assets/Game/Characters/Enemies/**/model.glb`) and dead
   archives (`TestDemo.zip` 62 MB, `RoD` 54 MB, several `Assets/Game/World/Starting…` 62–66 MB) are
   full binary blobs in history — every revision retained. **Fix (owner-run, rewrites history):**
   add `*.glb *.gltf *.zip` to `.gitattributes`, then `git lfs migrate import --include="*.glb,*.gltf,*.zip" --everything`;
   this alone should cut `.git` by multiple GB. Then `git reflog expire --expire=now --all && git gc --prune=now --aggressive`.
3. **De-duplicate models:** `Docs/models/` holds full copies (`iron-warden.glb` 57 MB,
   `enemy-ranged/elite/grunt.glb` ~55 MB each, plus `class-*`) that duplicate the rigs already under
   `Assets/Game/Characters/`. If `Docs/models/` is just reference exports, drop it from the repo
   (keep it in cloud storage) — it's pure duplication of tracked assets.
4. **Purge dead large blobs from history:** `TestDemo.zip`, `RoD`, orphaned `World/Starting`
   revisions — remove via the same `git lfs migrate` / `git filter-repo` pass while you're rewriting.

⚠ Steps 2–4 rewrite history → require a force-push and a fresh clone by any collaborator, and per
`CLAUDE.md` push/LFS auth isn't available to CLI sessions, so **this is an owner action**. Do it on
a quiet day, back up the repo first, and coordinate the re-clone. Step 1 is safe to do anytime.

## Keeping Sessions Cheap (context / token efficiency)  *(your follow-up ask)*

The costliest reads this session were the two status docs (~280 lines each) and large single files
(`AbilityCaster.cs` ~1650 lines, `GmConsole.cs` 600). Concrete levers:

1. **Keep SNAPSHOT/ROADMAP current and short.** They're read-first every session; when stale, a
   session re-derives state by scanning the tree (expensive) *and* can be misled. A tight, accurate
   SNAPSHOT is the highest-leverage token saver you have.
2. **Split the giant files.** `AbilityCaster.cs` at ~1650 lines is loaded whole whenever abilities
   come up. Splitting per-class cast logic into partial classes (`AbilityCaster.Warden.cs`, …) lets
   a session read only the relevant slice.
3. **Use the `crossworlds-dev` skill as the entry point** for dev tasks — it front-loads the
   conventions so a session doesn't re-read `CLAUDE.md` + `_CONTEXT` from scratch each time.
4. **Scope requests to files, not "the project."** "Fix the dodge i-frame in PlayerMovement/Health"
   costs a fraction of "audit combat." Point sessions at the 2–3 files when you already know where.
5. **Add the guard grep to the verification bar** so future sessions don't re-discover the same 31
   files. Encoding a known result in a doc is cheaper than re-finding it.
6. **A per-session `git status` that completes** — the repo is slow enough that even status timed
   out here. Shrinking `.git` (above) makes every git op a session runs faster and cheaper.
